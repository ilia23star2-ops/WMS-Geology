# AGENTS.md — протокол автономной работы агента

Читай первым, если работаешь агентом (Codespaces, локальный CLI, чат).
Цель: заход делается самостоятельно, человек только принимает результат.

## 0. Модель работы

Исполнитель с терминалом делает цикл сам: читает → правит → тесты → коммит → push → отчёт.
Чат-агент без терминала выдаёт один bash-блок на заход; новые файлы — вставкой в VS Code.

## 1. Старт

- Прочитать `RULES`, `PROJECT`, `CONTEXT`, `PLAN` (+ `API`/`DATABASE`/`UI` по теме).
- Машина: работа `/d/Dev/projects/WMS-Geology`, дом `/c/Projert/WMS-Geology`.
- `git branch --show-current`, `git status --short`, `git log --oneline -5`.
- Код читать по raw: `https://raw.githubusercontent.com/ilia23star2-ops/WMS-Geology/<ветка>/<путь>`
- Локально изменённый файл на GitHub не виден — запросить его текст.

## 2. Бюджет токенов

| Действие | Лимит | Как |
|---|---|---|
| Разведка | ≤ 300 строк за заход | `rg`, `sed -n`, не `cat` целиком |
| Файл целиком | только если < 250 строк | иначе диапазоны |
| Правка | ≤ 150 строк вывода | точечный `sed`/патч |
| Логи | ≤ 30 строк | `tail -n 30`, `grep -A5 FAIL` |
| Файлов в заходе | 1–3 | больше — дробить |
| Bash-блок | ≤ 30 строк | без символа доллара и heredoc |

Ориентир: заход ≈ 10–15k токенов. Один большой файл — одно сообщение.

## 3. Цикл захода

1. Объявить: номер захода, ветка, число файлов, число новых тестов.
2. Прочитать меняемые файлы (с учётом бюджета).
3. Правки → тесты → красное чинить в том же заходе.
4. Зелёное → commit + push → отчёт + device-check по стадиям.
5. Ждать «норм». Только потом merge в фичу, удаление ветки, доки.

## 4. Автономия

| Решаю сам | Спрашиваю человека |
|---|---|
| алгоритм, структура, имена | схема БД / миграция |
| какие тесты писать | публичный контракт API |
| как чинить упавший тест | удаление кода/файлов |
| установка зависимостей | больше 7 файлов |
| формулировки коммитов | изменение интерфейса |
| порядок правок в заходе | merge / удаление ветки / push в main |

## 5. Каркас bash-блока

Обязательно: тег `[Проверка]`/`[Правка+Тесты]`/`[Git]`/`[Тесты]`; `wms_clear` в начале;
сводка в `/tmp/wms_summary.txt` и `cat` на экран; `wms_report` в конце;
guard по маркерам правки; откат из бэкапа вместо `exit 1`; долгие операции — с прогрессом.

## 6. Чек-лист перед коммитом

- Backend `poetry run pytest -q`, Web `npm test` + `tsc --noEmit`, Mobile `flutter analyze` + `flutter test` — зелёные.
- `git add` — только явные имена. Никогда `git add .` на рабочем ПК.
- Не попали `mobile/android/*`, `*.hprof`, кэши, `node_modules`, `.dart_tool`.
- Доки обновлены в этой же пачке (`PLAN`, `CONTEXT`, `PROGRESS`; при контракте — `API`/`DATABASE`).
- Ветка — `fix/*` или `docs/*`, не `feature/3.x-migration` и не `main`.

## 7. Формат отчёта

Заход и ветка → что сделано (1–2 строки) → тесты (backend/web/mobile) →
hash коммита → что осталось локально (машинные файлы — норма) →
device-check для человека → следующий шаг.

## 8. Грабли WMS-Geology

| Грабли | Что делать |
|---|---|
| BOM в `mobile/android/gradle.properties` | отключает первую строку (`jvmargs`) → D8 OOM; снимать BOM |
| `work-pc-setup/setup.ps1` | шаг 2 удаляет `D:\Dev\maven-local`; `io/flutter` в паке нет — восстанавливать из кэша Gradle |
| `install_build_env.ps1` (WMS-Build-Pack) | не запускать: сносит `~/.gradle/caches`, копирует из несуществующих путей |

| Сборка APK на работе | офлайн: `maven-local` первым в `allprojects.repositories`, `--target-platform android-arm64` |

| applicationId | `com.wmsgeology.wms_geology_mobile` |

## 9. Приёмка

Юнит-тесты — не приёмка. После зелёных тестов выдать device-check по стадиям
(подготовка → сценарий → синхронизация → результат) с копипаст-командами,
ожиданием «что увидеть» и «что прислать». Заход закрывается только после «норм».
