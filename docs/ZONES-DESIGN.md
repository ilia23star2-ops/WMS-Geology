# ZONES-DESIGN.md — зоны напольного хранения (topology-zones)

Статус: дизайн согласован 2026-11-27. Реализация — пачками
(zones-backend → zones-web → zones-mobile).

## Домен

- **Zone** — место в комнате, куда рядами на пол складывается тара.
  Привязка: `Zone.room` FK (зона внутри комнаты).
- **ZoneRow** — ряд внутри зоны. Ориентация ряда — **на каждый ряд**:
  `ZoneRow.orientation` = `horizontal` | `vertical`.
- **FloorPlace** — место (позиция) в ряду; тара ставится друг на друга
  (стопка).
- **Адрес напольной позиции:** комната / зона / ряд / место / ярус-стопки
  (ярус считаем снизу вверх от 1).
- **Лимита хранения нет:** объём зон разный и зависит от тары, поэтому
  храним только **счётчик тары** (вычисляемый) по зоне/ряду/месту,
  без валидации лимита.
- **QR:** только зона и ряд — `WMSG:ZONE:<id>`, `WMSG:ROW:<id>`
  (автогенерация + PDF, как у секций/ячеек). Место и ярус-стопки —
  виртуальные, без QR.

## Модели (предложение, миграция после согласования)

- `Zone`: `room` FK, `code`, `name`; unique (`room`, `code`).
- `ZoneRow`: `zone` FK, `code`, `orientation`; unique (`zone`, `code`).
- `FloorPlace`: `row` FK, `code` (int); unique (`row`, `code`).
- `Container`: + `floor_place` FK null + `floor_level` int null
  (взаимно исключающе с `pallet`: тара либо на поддоне ячейки, либо
  на полу в стопке).

## API (предложение)

- CRUD: `/storage/zones/`, `/storage/zones/{id}/rows/`,
  `/storage/rows/{id}/places/`.
- `GET /storage/zones/{id}/scheme/` — ряды с местами и стопками
  (контейнеры по местам с уровнями) + счётчики тары.
- Перемещения: постановка тары в место/уровень через существующие
  movements с напольным адресом.

## UI

- **Web:** вкладка «Зоны» в топологии: схема зоны — ряды полосами по
  ориентации, места ячейками, высота стопки числом/столбиком;
  цвет по счётчику тары; CRUD зон/рядов/мест.
- **Mobile:** список зон + схема + скан `WMSG:ZONE` / `WMSG:ROW`
  (переход к зоне/ряду).

## Пачки
