## БЛОК 7. Инвентаризация

### Сценарий 7.1. Плановая инвентаризация комнаты

**Вводные:** Раз в квартал сверяем склад.

**Ручной (М + Р, планшеты)**

1. М создаёт сессию [Инвентаризация], выбирает комнату.
2. Система формирует список ожидаемых тар и проб.
3. Р идёт по ячейкам:
- Сканирует QR ячейки.
- Система: «Ожидается поддон с 5 тарами».
- Р сканирует QR каждой тары.
- Рабочий считывает номер пробы глазами / сканирует
  штрих-код / сканирует QR пробы → отмечает галочкой.
4. Система:
- Проверяет наличие каждой тары.
- Проверяет статусы проб внутри тар.
- Формирует `InventoryIssue` для расхождений.

### Сценарий 7.2. Обработка расхождений

**Ручной (М)**

1. М открывает [Расхождения] для сессии.
2. Видит список `InventoryIssue`:

| Тип | Пример |
|---|---|
| `CONTAINER_MISSING` | Тары нет в ячейке |
| `CONTAINER_MISPLACED` | Тара не на своей позиции |
| `CONTAINER_EXTRA` | Лишняя тара |
| `SAMPLE_MISSING` | Пробы нет в таре |
| `SAMPLE_STATUS_MISMATCH` | В БД `PICKED`, физически на месте |

3. По каждому:
- `CONTAINER_MISSING` → пометить «найти», временно убрать из системы.
- `CONTAINER_MISPLACED` → обновить позицию.
- `CONTAINER_EXTRA` → создать запись или пометить «разобраться».
- `SAMPLE_MISSING` → пометить.
- `SAMPLE_STATUS_MISMATCH` → разобраться вручную.
4. М отмечает `resolution` для каждого issue.

**Автоматика:**
- После завершения сессии формируется отчёт: «Найдено X,
расхождений Y, критичных Z».

### Сценарий 7.3. Инвентаризация с штрих-кодом

**Ручной (Р, планшет)**

1. Р сканирует ШК с этикетки тары/пробы.
2. Система сохраняет в `InventoryScan.raw_barcode`.
3. Сравнение с БД — по номеру пробы (ручной ввод или выбор).
4. Позже (когда формат ШК от ЛИМС будет известен) — добавим парсер.

### Сценарий 7.4. Проверка проб в таре

**Ручной (Р, планшет)**

1. Р сканирует QR ячейки.
2. Система: «Ожидается тара T-001 с 31 пробой».
3. Р открывает тару, сверяет пробы:
- Сканирует ШК каждой пробы (`raw_barcode`).
- Или отмечает чекбоксом на этикетке.
4. Система сверяет: что найдено, что нет, что лишнее.
5. Формирует `InventoryIssue` для расхождений.

## БЛОК 11. ПОРТАЛ ЛАБОРАТОРИИ

2. Нажимает [+ Создать рейс].
3. Заполняет:

- Откуда: Лаборатория А (авто по логину).
- Куда: Склад WMS Geology.
4. Нажимает [Создать].
5. Рейс → `status = DRAFT`. Открывается экран сборки.

### Сценарий 11.2. Сборка рейса — импорт из ЛИМС

**Ручной (Л, веб лаборатории)**

1. Л нажимает [📋 Импорт из ЛИМС].
2. Вставляет текст выгрузки в поле.
3. Нажимает [Распарсить].
4. Система:
- Разбивает на блоки (пустая строка + Н/З — новый блок).
- Для каждого блока:
  - Извлекает Н/З (вх / тек), тару, тип, участок.
  - Парсит список проб (строка = `п/п + пробел + номер`).
- Проверяет префиксы, типы, участки по справочникам.
5. Показывает результат:
- ✓ Найдено N блоков.
- ⚠ Ошибки: «Блок №2 — тип не найден».
6. Л проверяет, нажимает [Применить].

### Сценарий 11.3. Сборка рейса — ручной ввод с несколькими ТИ

6. Л может поправить вручную:

- `Ctrl+Click` — точечно.

7. Нажимает [Применить].

**Особенность:** один список проб дублируется для каждого выбранного
ТИ. Одна физическая проба становится несколькими `Sample` (навесками)

**Ручной (Л, веб лаборатории)**

**Ручной (Р, планшет)**

2. Р открывает [Приёмка] → видит рейс в «Ожидаемых».

- ✓ MATCHED.
- ⚠ DISCREPANCY.
- ❌ MISSING.

8. При расхождениях → `PARTIALLY_RECEIVED` + акт приёмки.

**Ручной (Л)**

3. Указывает причину.

**Ручной (А)**

### Сценарий 11.10. Возврат рейса

**Ручной (Р, планшет)**

2. Р → [Возврат] с комментарием.
3. `Shipment.status = RETURNED`.
4. Л видит статус и комментарий в портале.

### Сценарий 11.11. Справочник тары лаборатории

**Ручной (Л, веб лаборатории)**

1. Л открывает [Справочники] → [Типы тары].
2. Видит:

- Название, размер, вместимость.
- Привязывается к лаборатории.
4. Общие типы видит, но менять не может (только админ).
