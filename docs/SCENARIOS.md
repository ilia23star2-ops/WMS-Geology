## БЛОК 1. Приёмка

### Сценарий 1.1. Приёмка с Excel (двухфазная)

**Вводные:** Лаборатория отправила машину, менеджер получил Excel
из общей папки.

**Фаза 1. Предзаполнение (М, ПК)**

1. М открывает [Приёмка] → [Загрузить Excel].
2. Выбирает файл из общей папки.
3. Система парсит: «Одна лаборатория, N листов (участков),
   M нарядов. Создать партию?»
4. М видит предпросмотр:
   - Участок: Тестовый.
   - Наряд Тест001 / ШЛ: ожидается 5 тар.
   - Наряд Тест001 / ХА: ожидается 3 тары.
5. М подтверждает → `Receipt.status = EXPECTED`.
6. Создаются `ReceiptItem` со статусом `EXPECTED`.

**Фаза 2. Приёмка (Р, планшет)**

1. Р открывает [Приёмка] → видит активные партии.
2. Открывает `ПР-2026-001`.
3. Система: «Ожидается: 5 тар ШЛ, 3 тары ХА».
4. Р разгружает машину:
   - Сканирует QR тары (если есть) → `ReceiptItem.status = MATCHED`.
   - Или вводит номер тары вручную.
5. По каждой таре вводит пробы (см. Сценарий 1.3).
6. Если чего-то не хватает — система: «Ожидалось 5 тар, отсканировано 4.
   Отметить расхождение?»
7. `Receipt.status = CONFIRMED` или `DISCREPANCY`.

### Сценарий 1.2. Приёмка без Excel (ручной ввод)

**Вводные:** Excel нет, машина уже приехала.

**Ручной (Р, планшет)**

1. Р открывает [Приёмка] → [Создать партию вручную].
2. **Шаг 1. Партия:**
   - Текущий Н/З (с подсказками из справочника).
   - ☐ Входящий Н/З → раскрывается поле.
     - Если `linked_order` уже есть → автозаполнение.
     - Если нет → вводится вручную, сохраняется.
   - Тип исследования (справочник или [+ Новый]).
   - Кол-во тары.
   - Автоопределённые участок и лаборатория — read-only.
3. Р нажимает [Создать партию] → создаются черновики тар.
4. **Шаг 2. Заполнение тары** — см. Сценарий 1.3.

### Сценарий 1.3. Заполнение тары

**Ручной (Р, планшет)**

**Шапка тары** (авто):
- Участок, Н/З, Тип, Номер тары.

**Строка ввода:**
- № тары.
- Кол-во проб.

**Скважины:**

1. Нажимает [+ Добавить скважину].
2. Появляется строка: `[____|___|______] [✏]`
   - Префикс (например, `TAA-A34076001-`).
   - Порядковый (например, `001-031`).
3. По мере ввода — **подсказки** (ghost text):
   - Знакомые префиксы.
   - Похожие скважины.
   - Совпадения с другими тарами.
4. Нажимает [✏] → меню редактирования:
   - **Скважина** (опционально).
   - **Префикс.**
   - **Порядковый номер.**
   - **Отсутствуют** — `2, 4-7`.
   - **Выбраны** — `1, 8-9`.
   - ☐ Показать всё (развернуть на весь экран).
   - **Итого** (пересчёт автоматически).

**Проверка:**
- `Итого = диапазон − отсутствуют − выбраны`.
- Если `Итого = Кол-во проб` → **зелёный**.
- Иначе → **красный**, подсветка конкретной скважины.

**Кнопки:**
- [💬 Комментарий] — из справочника или своё.
- [👁 Предпросмотр] — вкладки: Список / Этикетка / QR.
- [Сохранить] — активна только при совпадении.

### Сценарий 1.4. Приёмка шифрованных проб

**Вводные:** Проба `TAA-A34076001-030`. Префикс `TAA-A` → Лаборатория А.

**Ручной (Р, планшет)**

1. Р вводит текущий Н/З и тип.
2. Автоопределение лаборатории по префиксу:
   - `TAA-A` → Лаборатория А.
3. Автоопределение участка по Н/З:
   - `02-Тест001` → Тестовый.
4. Р вводит диапазон: `TAA-A34076001-001` — `TAA-A34076001-030`.
5. Система создаёт 30 проб с `is_encrypted = TRUE`.
6. `Sample.number_prefix = TAA-A`, `number_middle = 34076001`,
   `number_sequence = 001..030`.
7. Скважина **не заполняется** — получим позже через ЛИМС.
8. `Sample.status = PENDING_DECRYPTION` (если скважина нужна для
   текущих операций).

### Сценарий 1.5. Приёмка нешифрованных проб

**Вводные:** Проба `TST124001`. Префикс `TST` → участок.

**Ручной (Р, планшет)**

1. Р вводит текущий Н/З и тип.
2. Автоопределение участка:
   - `TST` → Тестовый.
3. Р вводит диапазон: `TST124001` — `TST124015`.
4. Система создаёт 15 проб с `is_encrypted = FALSE`.
5. `Sample.number_prefix = TST`, `number_middle = 124`,
   `number_sequence = 001..015`.
6. `Sample.well = 124` (скважина определена).

### Сценарий 1.6. Расхождение с Excel — акт приёмки

**Ручной (М, ПК)**

1. При разгрузке обнаружено: Excel сказал 5 тар ШЛ, приехало 4.
2. Система создаёт `ReceiptItem` со статусом `MISSING`.
3. М открывает партию → видит расхождение.
4. М нажимает [Акт приёмки] → PDF:
   - От кого / кому.
   - Партия, дата, лаборатория.
   - Ожидалось: 5 тар.
   - Принято: 4 тары.
   - **Не приехало:** 1 тара (ШЛ).
5. М печатает, подписывает с водителем.
6. Один экземпляр — отправителю, один — нам.

## БЛОК 2. Размещение

### Сценарий 2.1. Размещение после приёмки

**Ручной (Р, планшет)**

1. Р открывает [Размещение].
2. Видит список тар `PENDING_PLACEMENT`.
3. Сканирует QR тары или ячейки.
4. Система показывает: «Тара T-001, 31 проба».
5. Р сканирует QR ячейки или выбирает её.
6. Система обновляет `Container.pallet_id` / `floor_room_id`.
7. Статус → `ACTIVE`.

### Сценарий 2.2. Массовое размещение

**Ручной (Р, планшет)**

1. [Размещение] → список `PENDING_PLACEMENT`.
2. Р выделяет несколько тар чекбоксами.
3. Нажимает [Разместить выбранные].
4. Сканирует целевую ячейку.
5. Система размещает все выбранные тары.
6. Статусы → `ACTIVE`.

### Сценарий 2.3. Виртуальный вид секции

**Ручной (Р, планшет)**

1. Р сканирует **QR секции** (внизу пролёта).
2. Открывается [Вид секции]:
Секция 1 (Стеллаж A, Комната 1)
├── Ярус D
│ ├── Ячейка 1: [занята] Поддон с 5 тарами
│ ├── Ячейка 2: [свободна]
│ └── Ячейка 3: [занята] Поддон с 3 тарами
├── Ярус C ...

text
3. Р кликает на ячейку → карточка:
- Что за поддон, какие тары, какие пробы.
- [Разместить поддон], [Извлечь], [Переместить].
4. Выполняет операцию.

## БЛОК 10. Печать

### Сценарий 10.1. Массовая печать этикеток / QR

**Ручной (Р или М, ПК)**

1. Открывает [Тары] → фильтр по партии / дате / статусу.
2. Выделяет тары чекбоксами.
3. [В корзину печати].
4. Открывает корзину:
- Выбрать: [Этикетки] или [Только QR].
5. Система рассчитывает раскладку на A4.
6. Показывает предпросмотр: сколько листов, как расположены.
7. [Печать] → PDF.
8. Распечатывает → клеит.

### Сценарий 10.2. Предпросмотр этикетки одной тары

**Ручной (Р, планшет)**

1. В карточке тары — [Предпросмотр].
2. Открывается окно с 3 вкладками:
- **Список проб** — таблица: п/п, проба, чекбокс.
- **Этикетка** — макет с QR.
- **QR** — только QR + ID.
3. Р проверяет, может распечатать.

2. **Формат штрих-кода ЛИМС** — как только узнаем, добавим парсер.

этикетки.
5. **Порог 1 колонка / 2 колонки** — эмпирически при тестовой печати.
6. **Подписант акта приёмки** — только наш сотрудник или с водителем?
7. **Расшифровка скважины** — источник и API ЛИМС (серия 2.x).
