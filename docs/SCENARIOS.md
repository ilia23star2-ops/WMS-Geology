3. Р кликает на ячейку → открывается карточка ячейки:
- Что за поддон, какие тары, какие пробы.

4. Р выполняет операцию.

**Автоматика:**
- Список ячеек и их содержимое подгружаются с сервера.
- Можно выбрать ячейку для точечной работы без лазания на ярус.

### Сценарий 2.3. Точечное сканирование ячейки

**Ручной (Р, планшет, стоя на стремянке):**

## БЛОК 5. Выборка (`PickList`)

### Сценарий 5.1. Создание списка выборки

**Ручной (М, ПК):**
1. М открывает [Выборка] → [Создать].
2. Вводит номер списка (или генерируется автоматически «В-2026-NNN»).
3. Добавляет пробы:
- По номеру.
- По Н/З.
- По участку.
- Через файл (CSV/Excel).
4. Сохраняет → `PickList.status = ACTIVE`.
5. Задача появляется у рабочих.

### Сценарий 5.2. Выборка проб рабочим

**Ручной (Р, планшет):**
1. Р открывает [Мои задачи] → [Выборка В-2026-001].
2. Видит список проб со статусами `PENDING`.
3. Для каждой:
- Р идёт по адресу (Комната / Стеллаж / Секция / Ярус / Ячейка).
- Открывает тару, **физически извлекает пробу**.
- Сканирует QR тары → система находит пробу внутри.
- Отмечает [Извлечена] → `PickListItem.status = PICKED`.
4. Если проба не найдена — [Не найдена] → `NOT_FOUND`.

**Автоматика:**
- `Sample.status` меняется на `ISSUED` (или новый статус `PICKED`).
- В `AuditLog`: кто, когда, откуда.
- Задача автоматически закрывается при 100% обработке.

### Сценарий 5.3. Отправка в лабораторию (`Shipment`)

**Ручной (Р или М):**
1. После выборки → [Создать отправку].
2. Выбирает пробы со статусом `PICKED`.
3. Указывает назначение (лаборатория, адрес).
4. Нажимает [Отправить] → `Shipment.sent_at = NOW()`.
5. `PickListItem.status = SENT`.
6. Можно распечатать сопроводительный документ.

## БЛОК 7. Инвентаризация

### Сценарий 7.1. Плановая инвентаризация комнаты

**Вводные:** Раз в квартал сверяем склад.

**Ручной (М + Р, планшеты):**
1. М создаёт сессию [Инвентаризация], выбирает комнату.
2. Система формирует список ожидаемых тар и проб.
3. Р идёт по ячейкам:
- Сканирует QR ячейки.
- Система: «Ожидается поддон с 5 тарами».
- Р сканирует QR каждой тары.
- Рабочий считывает номер пробы глазами / сканирует штрих-код / сканирует QR пробы (если есть) → отмечает галочкой.
4. Система:
- Проверяет наличие каждой тары.
- Проверяет статусы проб внутри тар.
- Формирует `InventoryIssue` для расхождений.

### Сценарий 7.2. Обработка расхождений

**Ручной (М):**
1. М открывает [Расхождения] для сессии.
2. Видит список `InventoryIssue`:

| Тип | Пример |
|---|---|
| `CONTAINER_MISSING` | Тары нет в ячейке |
| `CONTAINER_MISPLACED` | Тара не на своей позиции |
| `CONTAINER_EXTRA` | Лишняя тара |
| `SAMPLE_MISSING` | Пробы нет в таре |
| `SAMPLE_STATUS_MISMATCH` | В БД `PICKED`, физически на месте |

3. По каждому:
- **`CONTAINER_MISSING`** → пометить «найти», временно убрать из системы.
- **`CONTAINER_MISPLACED`** → обновить позицию.
- **`CONTAINER_EXTRA`** → создать запись или пометить «разобраться».
- **`SAMPLE_MISSING`** → пометить.
- **`SAMPLE_STATUS_MISMATCH`** → разобраться вручную.
4. М отмечает `resolution` для каждого issue.

**Автоматика:**
- После завершения сессии формируется отчёт: «Найдено X, расхождений Y, критичных Z».

### Сценарий 7.3. Инвентаризация с штрих-кодом

**Ручной (Р, планшет):**
1. Р сканирует ШК с этикетки тары/пробы.
2. Система сохраняет в `InventoryScan.raw_barcode`.
3. Сравнение с БД — по номеру пробы (ручной ввод или выбор).
4. Позже (когда формат ШК от ЛИМС будет известен) — добавим парсер.

## БЛОК 8. Помощник по сортировке

### Сценарий 8.1. Рекомендация ячейки для готового поддона

**Ручной (Р, планшет):**
1. Р сформировал поддон (Сценарий 1.2).
2. Нажимает [Куда поставить?].
3. Система анализирует содержимое поддона и свободные ячейки:
- Участок → Н/З → тип исследования → соседние номера тар.
4. Показывает top-5 ячеек с обоснованием:
- «Ячейка A-01-B-3 — там 3 тары с участка №5».
- «Ячейка A-01-C-1 — там 2 тары с того же Н/З».
5. Р выбирает и размещает.

### Сценарий 8.2. Рекомендация для одиночной тары

**Ручной (Р, планшет):**
1. Р сканирует тару после приёмки.
2. Нажимает [Куда положить?].
3. Система: «На поддон в ячейке A-01-A-2 — там 2 тары с того же участка».

### Сценарий 8.3. Раскладка пула по N поддонам

**Ручной (Р, планшет):**
1. Р открывает [Раскладка пула].
2. Сканирует N тар (или указывает пул из приёмки).
3. Указывает количество поддонов (например, 2).
4. Нажимает [Разложить].
5. Система:
- Группирует тары по критериям.
- Распределяет на 2 поддона.
- Показывает: «Поддон 1: тары A, B, C. Поддон 2: тары D, E».
6. Р подтверждает или корректирует.

**Автоматика (MVP):**
- Без веса и объёма.
- Без автоматического подбора N.
- Без bin packing.
- Без маршрута обхода.
