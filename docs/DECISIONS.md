## 1. Решения

### 1.1. 2026-10-07 — Название проекта

**Решение:** `WMS Geology`.

**Причина:** Коротко, отражает домен (геология) и класс системы (WMS).
Читается одинаково на русском и английском.

**Где:** `README.md`, `PROJECT.md`.

**Статус:** ✅ действует.

---

### 1.2. 2026-10-07 — Стек технологий

**Решение:**
- БД: PostgreSQL 16+.
- Бэкенд: Python 3.12 + Django + DRF.
- Мобильное: Flutter (Android-планшет).
- Веб: React + TypeScript.

**Причина:**
- PostgreSQL — стандарт для WMS, JSONB для `legacy_data`,
  готовность к PostGIS.
- Python/Django — быстрый старт, встроенная админка, экосистема.
- Flutter — единый код для Android, работа с камерой.
- React — гибкость, много UI-библиотек.
- Все компоненты — под MIT/Apache/BSD → свободно для коммерции.

**Где:** `PROJECT.md` §Стек.

**Статус:** ✅ действует.

---

### 1.3. 2026-10-07 — Наряд-заказы: self-reference (Вариант A)

**Решение:** `WorkOrders.linked_order_id` (self-reference).
Типы: `INCOMING` и `CODED`.

**Причина:**
- Один входящий может быть связан с несколькими кодированными.
- Не масштабируется при появлении третьего типа названий.
- Self-reference честно отражает реальность.

**Где:** `docs/DATABASE.md`.

**Статус:** ✅ действует.

---

### 1.4. 2026-10-07 — Проба как единица хранения

**Решение:** `Samples` — физическая единица хранения. Одна строка =
одна проба с конкретным типом исследования в конкретной таре.
Таблица `SampleParts` **не создаётся**.

**Причина:**
- Разделение проб по типам — вне WMS (в лабораториях).
- WMS фиксирует результат.
- Тип исследования — ключевой критерий поиска.

**Где:** `docs/DATABASE.md`, `PROJECT.md` §Домен.

**Статус:** ✅ действует.

## 2. Что не делаем и почему

- **Не используем `SampleParts`.** Разделение — вне WMS (см. 1.4).
- **Не храним две колонки для Н/З.** Не масштабируется (см. 1.3).
- **Не заставляем лаборатории использовать наш формат на старте**
  (см. 1.9).
- **Не переклеиваем старые этикетки** (см. 1.8).
- **Не используем закрытые лицензии в ядре.**
- **Не пишем детальные API-контракты до появления моделей** —
  уточним в серии 1.1 по факту.

## 3. Глоссарий

### Данные

| Термин | Что значит |
|---|---|
| **Проба (Sample)** | Физическая единица хранения. Пара (номер, тип исследования) в таре. |
| **Наряд-заказ (Н/З)** | Группа проб. Тип `INCOMING` или `CODED`. |
| **Входящий Н/З** | Название до шифровки. |
| **Зашифрованный Н/З** | Название после шифровки. |
| **Тип исследования** | Ключевой критерий (шлифы, химия, изотопы). |
| **Тара (Container)** | Физический контейнер. Пробы одного типа. |
| **Поддон (Pallet)** | Платформа для тар. В ячейке или на полу. |
| **Ячейка (Cell)** | Слот на ярусе. До 3 поддонов. |
| **Адрес** | Комната / Стеллаж / Пролёт / Ярус / Ячейка. |
| **Участок (Site)** | Место отбора проб. |
| **Скважина (Well)** | Источник пробы. |

### Процесс

| Термин | Что значит |
|---|---|
| **Шифровка** | Присвоение Н/З нового названия. |
| **Приёмка** | Поступление тары с пробами. |
| **Размещение** | Привязка тары к ячейке / поддону / полу. |
| **Перемещение** | Изменение адреса тары. |
| **Инвентаризация** | Сверка физического наличия с системой. |
| **Наряд-задание** | Задача кладовщику. |
| **Жизненный цикл** | История пробы. |

### UI

| Термин | Что значит |
|---|---|
| **Дашборд** | Главный экран. |
| **Сканер** | Экран сканирования QR. |
| **Sidebar** | Боковое меню. |
| **Панель быстрого доступа** | Плитки на дашборде. |

## 4. Что НЕ значат эти термины

- «**Часть пробы**» — не используется в WMS.
- «**Ячейка**» — слот на **до 3 поддонов**.
- «**Наряд-заказ**» — входящий и зашифрованный — **разные строки**.
- «**Проба**» — не уникальна по номеру.
