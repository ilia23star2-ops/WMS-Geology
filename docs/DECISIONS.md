### 1.14. 2026-10-07 — Портативный PostgreSQL вместо установки

**Решение:** используем **портативный PostgreSQL**, развёрнутый
в `D:\Dev\pgsql\`, вместо:
- Локальной установки PostgreSQL (требует прав администратора).
- Docker Desktop (требует прав администратора и ~500 МБ).
- SQLite (не потренируем JSONB, GIN-индексы).
- Облачного PostgreSQL (интернет-зависимость).

**Причина:**
- На рабочей машине **нет прав администратора**.
- Портативный PostgreSQL не требует установки — только распаковка.
- Полноценный PostgreSQL: JSONB, индексы, транзакции.
- Полная изоляция: всё в одной папке, легко снести.
- Совместимость с CI: тот же движок, что в `.github/workflows/ci.yml`.

**Как развёрнут:**
- Бинарники: `D:\Dev\pgsql\pgsql\bin\` (PostgreSQL из EDB binaries).
- Данные: `D:\Dev\pgsql\pgdata\` (создан `initdb`).
- Пароль суперпользователя при initdb передан через `--pwfile`.
- `postgresql.conf`: `listen_addresses = 'localhost'`.
- База `wms_geology`, пользователь `wms_user` / `wms_password`.
- Порт `5432`.

**Ограничения:**
- Локаль кластера — `Russian_Russia.1251` (может влиять на
  сортировку кириллицы). Возможный техдолг — пересоздать кластер
  с `--locale=C` или `--locale=en_US.UTF-8`.
- Сервер не является службой Windows — запускается вручную через
  `pg_ctl`. При перезагрузке ПК нужно запускать снова.

**Где:** `backend/.env`, `CONTEXT.md`.
**Статус:** ✅ действует.

### 1.15. 2026-10-07 — Все Django-команды через `poetry run`

**Решение:** запускать `manage.py` и любые Python-скрипты
бэкенда **только** через `poetry run python ...` из терминала.

**Причина:**
- Системный Python (`D:\Dev\python\python.exe`) не имеет Django —
  он установлен в `.venv/`.
- VS Code при нажатии «Run» использует системный Python и падает
  с `ModuleNotFoundError: No module named 'django'`.
- `poetry run` гарантированно использует виртуальное окружение
  проекта.

**Где:** `PROJECT.md` §Команды, `CONTEXT.md` §Грабли.
**Статус:** ✅ действует.

## 2. Что не делаем и почему

- **Не используем `SampleParts`.** Разделение — вне WMS.
- **Не храним две колонки для Н/З.** Не масштабируется.
- **Не заставляем лаборатории использовать наш формат.**
- **Не переклеиваем старые этикетки.**
- **Не используем закрытые лицензии в ядре.**
- **Не ставим PostgreSQL или Docker Desktop нативно.**
  Нет прав администратора. Портативный PostgreSQL — решение.
- **Не используем SQLite для разработки.** У нас есть
  полноценный PostgreSQL.
- **Не запускаем Django-команды через кнопку «Run» в VS Code.**
  Только `poetry run` из терминала.

## 3. Глоссарий

### Данные

| Термин | Что значит |
|---|---|
| **Проба (Sample)** | Физическая единица хранения. Пара (номер, тип исследования) в таре. |
| **Наряд-заказ (Н/З)** | Группа проб. Тип `INCOMING` или `CODED`. |
| **Входящий Н/З** | Название до шифровки. |
| **Зашифрованный Н/З** | Название после шифровки. |
| **Тип исследования** | Ключевой критерий (шлифы, химия, изотопы). |
| **Тара (Container)** | Физический контейнер. Пробы одного типа. |
| **Поддон (Pallet)** | Платформа для тар. В ячейке или на полу. |
| **Ячейка (Cell)** | Слот на ярусе. До 3 поддонов. |
| **Адрес** | Комната / Стеллаж / Пролёт / Ярус / Ячейка. |
| **Участок (Site)** | Место отбора проб. |
| **Скважина (Well)** | Источник пробы. |

### Процесс

| Термин | Что значит |
|---|---|
| **Шифровка** | Присвоение Н/З нового названия. |
| **Приёмка** | Поступление тары с пробами. |
| **Размещение** | Привязка тары к ячейке / поддону / полу. |
| **Перемещение** | Изменение адреса тары. |
| **Инвентаризация** | Сверка физического наличия с системой. |
| **Наряд-задание** | Задача кладовщику. |
| **Жизненный цикл** | История пробы. |

### Инфраструктура

| Термин | Что значит |
|---|---|
| **Портативный PostgreSQL** | PostgreSQL без установки в систему, всё в папке `D:\Dev\pgsql\`. |
| **Кластер** | Совокупность баз данных, управляемых одним сервером. Хранится в `pgdata`. |
| **`poetry run`** | Запуск команды в виртуальном окружении проекта. |

### UI

| Термин | Что значит |
|---|---|
| **Дашборд** | Главный экран. |

## 4. Что НЕ значат эти термины

- «**Часть пробы**» — не используется в WMS.
- «**Ячейка**» — слот на **до 3 поддонов**.
- «**Наряд-заказ**» — входящий и зашифрованный — **разные строки**.
- «**Проба**» — не уникальна по номеру.
- «**Установка PostgreSQL**» — в нашем случае это распаковка
  портативной версии, не установка службы.
